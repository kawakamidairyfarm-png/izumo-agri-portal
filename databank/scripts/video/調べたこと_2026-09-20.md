# 動画づくりが見にくかった理由と、直せる見込み（2026-09-20 調査メモ）

使用者の判断（9/20）: いまの作り方では見にくいので止める。毎朝の自動生成は休止した。
このメモは「もっと良い作り方があるか」を調べた記録。次に再開するときの出発点。

## 根っこの原因（1つ）

**話している言葉の時刻が、1回の配信につき6か所（podyの章）しか分からない。**

- 19分の話に対して手がかりが6つ。章の中の何分何秒に何を言っているかは、まったく分からない
- だから画面は「章の窓の中に均等に並べる」しかなく、声が先に進んでも画面が止まる／声より先に画面が出る
- しかも pody の章は付け間違いがある（3秒しかない章、雑談まで含む章）
- 配色・書体・折り返し・1枚の長さは直せた。しかし時刻が無い限り「声と画面が合わない」は直らない

## 調べた結果

### LISTEN（listen.style）の文字起こし
- 1話ページに文字起こしが 328 の発話に分かれて載っている（`data-segment-index`）
- しかし時刻は **3分おきの8か所だけ**（`data-time="00:01" "03:03" "06:05" …`）。発話ごとの時刻は無い
- → pody の6か所より少し細かいが、画面を合わせるには足りない

### 音声認識で時刻を自分で作る（実測）
- whisper-small（int8・CPU 4コア・sherpa-onnx）で 729 秒の音声 → **710 秒で処理（実時間の1.0倍）**
  GitHub Actions の runner も4コアなので、19分の回なら 20 分弱で終わる。無料
- 文字の精度は粗い（乳脂肪率→入手防率、殺菌→作金）。ただし**時刻は正しく、手がかり語は拾える**
- 台本の17枚を、認識結果の「手がかり語」で音声に当ててみた → **11枚が順番どおりの時刻に当たった**
  （25秒刻み・弱いモデルでこの結果。文ごとに切る＋日本語向けモデルなら上がる）
- モデルは Hugging Face からは取れない（この環境から遮断）。GitHub の配布物（sherpa-onnx の releases）なら取れる
  日本語向けは `sherpa-onnx-zipformer-ja-reazonspeech-2024-08-01`（713MB）が候補。未計測

### 手元にある材料
- 41本の予定のうち **37本は全文がある**（data/transcripts）。無いのは note 有料記事の4本だけ
- 全文があれば、音声認識の粗い文字と全文を突き合わせて、**全文の1文ごとに時刻を付けられる**
  （認識結果は時刻のため、文字は全文のものを使う＝精度の問題が消える）

### 調べた作法（出典は会話ログ）
- 字幕ありの動画は視聴維持率が最大15%上がる。自動字幕の精度が低いと離脱する
- スライド動画は1枚 3〜8 秒が普通（いまは5.7秒＝ここは合っている）
- 字幕（セリフを追う）とテロップ（要点の演出）は別物。理想は併用

## 直せる見込み（案）

### 案1 音声認識で時刻を作り、画面を「言葉」に合わせる
1. Actions で音声認識（asr.yml・作成済み）→ 文ごとの時刻
2. 全文がある回は、全文の1文ごとに時刻を付ける（粗い認識文字との突き合わせ）
3. 台本の各画面を、手がかり語で「その言葉が出た時刻」に置く（試した方法。11/17 が当たった）
4. あわせて **字幕を焼き込む**（時刻つきの全文がそのまま字幕になる）
- 見込み: 声と画面のずれが「章単位」から「文単位」になる。字幕で見やすさが上がる
- 手間: 作り方の変更は中くらい。1本あたりの処理時間は +20 分（無料）
- 残る弱さ: 10分の一人語りをスライドで見せる形そのものは、YouTube では強い形ではない

### 案2 長い動画をやめ、60〜90秒の縦型（ショート）にする
- 1回の配信から「質問→答え」の一番いい1〜2分だけを切り、字幕を焼き込む
- 短いので画面は1〜3枚でよく、ずれの問題がほぼ消える
- Instagram リール／YouTube ショート／TikTok に同じものを出せる（TikTok から質問が来ている＝相性がよい）
- 案1の1〜2（時刻づくり）はここでも使う。切る位置を決めるのに要る
- 手間: 案1より小さい。台本は「どの1分を切るか」を決めるだけ

### 案3 動画をやめ、音声のまま YouTube に出す（podcast 形式）
- YouTube は RSS からポッドキャストを取り込める。画面はサムネイル1枚
- 手間ゼロ。ただし「教材」にはならない

## 勧め
- 再開するなら **案2**。同じ時刻づくり（案1の土台）を使って、短いものから当たりを見る
- 案1の長い動画は、案2で手応えがあってから
- どちらも、まず asr.yml を1本走らせて、日本語向けモデルの速さと精度を測るのが最初の一歩

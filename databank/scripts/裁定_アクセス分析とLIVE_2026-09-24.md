## 明鏡: 誰の・どんな変化か

- 「LIVEでデータバンク見ています」と言う人は、**もう関係ができている人**（部族の内側）。初めての人向けの受け皿（メルマガ）は、この人たちには合っていない。数字でもメルマガのクリックは 0。
- この人たちの望ましい変化は「LIVEで聞いた話を、あとで読み返せる／自分の質問が答えになって残る」。つまりデータバンクは **LIVEの予習・復習の場** であり、質問が回る場。
- 柱6（関係→文化→経済）: 「見ています」の一言は文化の芽。これを儀式にする（LIVEで「データバンクの◯◯の回」と言う → 見た人がコメントする → 次のLIVEで拾う）。経済（note・メルマガ）はその後ろ。
- 柱2（導線）: **口で言える住所が無い**。LIVEで「kawakamidairyfarm-png.github.io/izumo-agri-portal」は言えない。見ている人は「直接」か検索（Yahoo・Google）でたどり着いている。LIVE→データバンクの道がいちばん細い穴。

## 軍配: 打ち手（効く順）

1. **口で言える住所を持つ**（戦略宣言級・使用者の作業あり）
   - 独自ドメイン `databank.kawakamifarm.net`（9/13に保留した案）。LIVEで「データバンク・カワカミファーム・ドット・ネット」と言える。
   - 作業: 使用者がドメイン業者の画面で CNAME `databank` → `kawakamidairyfarm-png.github.io` を1行足す。残り（CNAMEファイル・絶対URL・Search Console）はこちら。
   - つなぎとして、LIVEでは「『川上牧場 データバンク』で検索」と言う（Yahoo経由の 2 件はこの形）。

2. **LIVEを見ている人の入口 /live を作る**（KPI宣言）
   - 中身: 「今日のLIVEで話した回」（手で 1〜3 本を足せる）、「LIVEで聞けなかったことはLINEへ（次のLIVEで答えます）」、LIVEで答えた質問の一覧（/questions へ）。
   - 次の一歩は **LINEで質問** を主に。メルマガは添えるだけ。
   - LIVEの固定コメント・プロフィールに `…/live?utm_source=live` を置く。

3. **計測の穴を塞ぐ**（Green・すぐできる）
   - 機械（Googlebot・Search Console のテスト・自動ブラウザ）を記録しない。
   - `?utm_source=live` を来た元として数える（2 と組）。
   - 18:30 の訪問が本人のスマホなら、スマホで `?keisoku=off` を一度開く。

## KPI宣言（2 と 3 を打つ場合）

- 動かすKPI: LIVE経由の訪問数（utm_source=live）と、そこからの LINE 質問クリック。
- 変化への接続: LIVEで聞いた人が、あとで読み返し、次の質問を送る。
- 仮説: 口で言える入口と「質問はLINEへ→次のLIVEで答える」の約束があれば、「見ています」がクリックと質問に変わる。
- 根拠: 人の訪問が 18〜19時台に集中（実測）、メルマガ 0 クリック（実測）。「/live が効く」は勘。
- 計測: 10/10 の30日レビューで、live の訪問・LINE クリック・/questions の閲覧を見る。
